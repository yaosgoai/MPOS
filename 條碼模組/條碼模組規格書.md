# 條碼模組 — 規格書

> 模組版本：**1.0.0**（2026-10-24）  
> 來源：由 IPC2DO 待辦管理系統的條碼掃描功能抽出，改為可給其他專案引用的獨立模組  
> 狀態：程式已建立；網頁規則已通過測試，Android 純 Java 部分已通過本機編譯與測試，**Android 整體（相機畫面、WebView 橋接）尚未實機建置測試**（見第 11 章）  
> 本規格是驗證規則與投票邏輯的**唯一依據**：Android（Java）與網頁（JavaScript）兩邊都必須照本規格實作，並通過 `test/vectors.json`

## 1. 目的與範圍

| 項目 | 內容 |
|---|---|
| 目的 | 提供「用手機或電腦相機讀取條碼，取得內容文字」的共用元件，各系統不必各自實作 |
| 平台 | Android App（原生畫面）、網頁（瀏覽器相機、照片辨識）、App 內嵌網頁（WebView 橋接到原生掃描） |
| 提供 | 即時掃描、照片辨識、讀值驗證、防誤讀投票、確認畫面、統一的結果格式 |
| 不提供 | 產生條碼、批次連續掃描、條碼內容的業務解析（例如 GS1 欄位拆解，由呼叫端處理） |

## 3. 支援格式

格式代碼兩平台一致（小寫加底線）。

| 代碼 | 名稱 | 類型 | 驗證規則（第 5.1 節） | 需讀到次數 |
|---|---|---|---|---|
| `qr_code` | QR Code | 二維 | 無（本身有錯誤更正） | 2 |
| `data_matrix` | Data Matrix | 二維 | 無 | 2 |
| `pdf417` | PDF417 | 二維 | 無 | 2 |
| `aztec` | Aztec | 二維 | 無 | 2 |
| `ean_13` | EAN-13 | 一維 | 13 碼數字＋檢查碼 | 3 |
| `ean_8` | EAN-8 | 一維 | 8 碼數字＋檢查碼 | 3 |
| `upc_a` | UPC-A | 一維 | 12 碼數字＋檢查碼 | 3 |
| `upc_e` | UPC-E | 一維 | 6～8 碼數字 | 3 |
| `code_128` | Code 128 | 一維 | 至少 2 字 | 3 |
| `itf` | ITF（交錯式 25 碼） | 一維 | 偶數碼、**至少 8 碼**；14 碼另驗 GS1 檢查碼 | 3 |
| `code_39` | Code 39 | 一維 | 至少 3 字，限 `0-9 A-Z - . $ / + % * 空白` | 4 |
| `code_93` | Code 93 | 一維 | 至少 3 字 | 4 |
| `codabar` | Codabar | 一維 | 去掉起訖字元 A～D 後至少 4 字 | 4 |

> ITF 注意：讀值常比條碼下方印的數字多 1 碼（最後一碼為檢查碼）。例：印 `266643201`，讀值 `2666432011`。

## 4. 辨識流程

### 4.1 即時掃描

| 平台 | 主要引擎 | 備援引擎 | 讀取範圍 |
|---|---|---|---|
| Android 原生 | Google ML Kit Barcode Scanning（全部格式） | ZXing（一維條碼） | ML Kit：外框（放寬 3%）包含畫面中心、多個時取最接近十字者；ZXing：穿過十字的水平帶 |
| 網頁 | 瀏覽器內建 `BarcodeDetector`（有支援時） | ZXing-js（一維條碼每 2 張畫面試一次；沒有內建辨識時二維碼也用 ZXing） | 同上 |

- 每 150ms（網頁）或每張相機畫面（Android）辨識一次
- Android 分析影像解析度目標 1920×1080（預設 640×480 讀不到細條碼）
- 對焦：畫面中央，點畫面重新對焦（Android）

### 4.2 ZXing 備援（水平帶）

| 參數 | Android（ZxingFallback） | 網頁（runScanner） |
|---|---|---|
| 水平帶寬度 | 轉正後畫面寬 92% | 畫面寬 92%、78%、64%、50% |
| 水平帶高度 | 畫面高 12%、20% | 畫面短邊 12% |
| 縮放 | 100%、80%、65%、50%、40%（面積平均縮小） | 換算到約 1400px 寬 × 100%、70% |
| ITF 允許長度 | 6～24 碼偶數 | 同左 |
| 影像旋轉 | 依相機 rotationDegrees 轉正（0／90／180／270） | 影片已轉正 |

> 為何要多種縮放：實測 ZXing 對一維條碼的線寬很敏感，同一張照片只在特定縮放比例讀得到（`test/images/itf_2666432011_a.jpg` 整張只在 80% 讀得到）。只用 100% 時兩張照片 12 種組合全部失敗；改為 100／80／65／50／40% 後 12 種全部讀出。

### 4.3 照片辨識（網頁 `decodeFile`）

依序嘗試，讀到且通過驗證即回傳：
1. 瀏覽器內建 `BarcodeDetector`（全部支援格式）
2. jsQR（只認 QR；有允許 `qr_code` 時）
3. ZXing-js：整張與水平帶（高 15%、每次移半帶），長邊縮放到 1200／1600／900／700px，0° 與 90°
4. zxing-cpp WebAssembly（`zxing-wasm`）：對反光、條碼前後空白不足的照片較強

## 5. 防誤讀規則

### 5.1 驗證（`BarcodeRules.isValid` ／ `BarcodeScan.validate`）

- 共同：不可空白；不可含解碼失敗替代字元 `U+FFFD`；不可含控制字元（換行、CR、Tab 與 GS1 分隔符 `0x1D` 除外）
- 各格式規則見第 3 章
- EAN／UPC／ITF-14 檢查碼：GS1 Mod 10（由右往左第 2 碼起，奇數位 ×3、偶數位 ×1，加總後補到 10 的倍數）

### 5.2 需讀到次數（`requiredReads`）

二維碼 2 次；EAN／UPC／Code 128／ITF 3 次；Code 39／Code 93／Codabar 4 次（無檢查碼、易誤讀）。

### 5.3 投票（`ReadVoter` ／ `createVoter`）

- 每次讀到通過驗證的值，記下時間；**同一內容在 2.5 秒內累計達需讀到次數即採用**
- 沒讀到、或讀值不合格的畫面**不歸零**（細條碼常漏讀，舊版「連續 N 張一致」會一直重來）
- **部分讀取防呆**：視窗內若有更長且包含此內容的讀值，較短者不採用（ITF 常讀出半段，例 `66643201`）
- 採用後清空投票；確認畫面按「重新掃描」也清空

### 5.4 確認畫面

`confirm=true`（預設）時：讀到後凍結當下畫面（取景框正方形）、顯示格式、比對次數與內容，按「✔ 正確，使用」才回傳；「↻ 重新掃描」繼續掃描。

## 6. 對外介面

### 6.1 掃描選項

| 欄位 | 型別 | 預設 | 說明 |
|---|---|---|---|
| `formats` | 字串陣列 | 空＝全部 | 只接受這些格式代碼 |
| `confirm` | 布林 | true | 是否顯示確認畫面 |
| `hint` | 字串 | 內建提示 | 畫面下方提示文字 |
| `voteWindowMs` | 數字 | 2500 | 投票時間視窗 |
| `zxingFallback` | 布林 | true | （Android）ML Kit 讀不到時用 ZXing |
| `requestId` | 字串 | 空 | （Android）原樣帶回結果，WebView 橋接用 |
| `mode` | 字串 | `auto` | （網頁 scanLive）`auto`／`native`／`inline`／`popup` |
| `scanPageUrl` | 字串 | — | （網頁 scanLive）掃描頁網址，`popup` 模式必填 |

### 6.2 Android

```java
// Activity／Fragment 的 onCreate 註冊
ActivityResultLauncher<ScanOptions> scan = registerForActivityResult(new ScanContract(), r -> {
    if (r.isOk()) use(r.text, r.format);          // 例：r.text="2666432011"、r.format="itf"
    else if (ScanResult.ERROR.equals(r.status)) showError(r.error);
});
// 需要掃描時
scan.launch(new ScanOptions().confirm(true).formats("itf", "ean_13"));
```

- 相機權限：模組自行要求；使用者拒絕時回傳 `status=error, error=camera_permission`
- 另可直接使用 `BarcodeRules`、`ReadVoter`、`ZxingFallback`（例如自建掃描畫面）

### 6.3 結果格式（兩平台一致）

| 欄位 | 說明 |
|---|---|
| `status` | `ok`／`cancel`／`error` |
| `text` | 條碼內容（`ok` 時） |
| `format` | 格式代碼（`ok` 時） |
| `engine` | 辨識引擎：`mlkit`／`zxing`／`native`（瀏覽器內建）／`jsqr`／`zxing-wasm` |
| `error` | 錯誤代碼（第 6.5 節） |

### 6.4 網頁（`barcode-scan.js`，全域 `BarcodeScan`）

| 函式 | 說明 |
|---|---|
| `scanLive(opts)` → Promise\<結果\> | 即時掃描；`auto` 依序：① App 原生（`window.BarcodeBridge`）② 本頁相機（最上層頁面且可用相機）③ 掃描頁新視窗 |
| `runScanner(opts)` → Promise\<結果\> | 直接在本頁開全螢幕相機掃描 |
| `decodeFile(file, opts)` → Promise\<結果 或 null\> | 照片辨識 |
| `validate(format, text)` | 驗證規則 |
| `requiredReads(format)` | 需讀到次數 |
| `createVoter(windowMs)` | 投票器：`add(format, text, nowMs?)`、`reset()` |
| `normFormat(name)` | 各引擎格式名稱轉成本模組代碼 |
| `cameraAllowed()` | 本頁是否允許使用相機 |
| `config` | 外部元件網址與 SRI 雜湊（第 8 章） |
| `version`、`FORMATS`、`LABELS` | 版本、格式清單、顯示名稱 |

```html
<script src="https://<部署網域>/barcode/v1/barcode-scan.js" integrity="sha384-…" crossorigin="anonymous"></script>
<script>
  BarcodeScan.scanLive({ scanPageUrl: 'https://<部署網域>/barcode/v1/scan.html' })
    .then(r => { if (r.status === 'ok') document.getElementById('desc').value += '\n' + r.text; });
</script>
```

### 6.5 錯誤代碼

| 代碼 | 意義 |
|---|---|
| `camera_permission` | 使用者拒絕相機權限 |
| `camera_unavailable` | 無相機、相機被占用，或此頁不允許使用相機 |
| `engine_unavailable` | 辨識元件載入失敗（網路或 CDN 被擋） |
| `popup_blocked` | 瀏覽器擋住掃描頁視窗 |
| `no_scan_page` | 需要掃描頁但未提供 `scanPageUrl` |
| `native_unavailable` | 指定 `native` 但不在支援的 App 內 |
| `invalid_result` | 回傳內容未通過驗證（不應發生，防偽造） |
| `bad_request` | （WebView 橋接）請求格式錯誤 |

## 7. 通訊協定

### 7.1 訊息格式（版本 v=1）

```json
// 請求（網頁 → App 原生）
{ "t": "barcode-scan", "v": 1, "id": "<32 碼隨機 hex>", "formats": ["itf"], "confirm": true, "hint": "…" }
// 結果（App 原生／掃描頁 → 呼叫端）
{ "t": "barcode-result", "v": 1, "id": "<同請求>", "status": "ok", "text": "2666432011", "format": "itf", "engine": "zxing" }
```

- `id` 由呼叫端以 `crypto.getRandomValues` 產生，結果必須帶回相同 `id`，呼叫端只接受相符者

### 7.2 掃描頁（新視窗）模式

1. 呼叫端開啟 `scan.html?id=<id>&origin=<呼叫端 location.origin>&confirm=1&formats=itf,ean_13`
2. 掃描頁只把結果以 `window.opener.postMessage(結果, origin)` 送給 **origin 參數指定的來源**（不用 `'*'`）；`origin` 須為 `https://` 網域格式，可再以 `ALLOWED_ORIGINS` 限定
3. 呼叫端只接受 `e.origin === 掃描頁網域`、`e.source === 自己開的視窗`、`id` 相符的訊息
4. 掃描頁被關閉時，呼叫端回傳 `cancel`

### 7.3 App 內 WebView 橋接

- Android 以 `androidx.webkit` 的 `WebViewCompat.addWebMessageListener` 注入 `BarcodeBridge`，**只注入到允許來源的頁面**（可含 iframe），結果只回覆給發出請求的那個頁面
- 不使用 `addJavascriptInterface`、不廣播 `postMessage('*')`
- 允許來源規則不可為 `*`；例：`https://yaosgoai.github.io`、`https://*.googleusercontent.com`（後者代表任何 Apps Script 頁面都能「啟動掃描」，但只會收到自己請求的結果）
- 網頁端不需改程式：`scanLive()` 偵測到 `window.BarcodeBridge` 會自動改用原生掃描
- WebView 版本太舊（不支援 WEB_MESSAGE_LISTENER）時 `install()` 回傳 null，網頁自動改用其他方式

## 12. 版本規則

- 語意化版本 `主.次.修`：改了對外介面或結果格式 → 主版號；新增功能且相容 → 次版號；修正 → 修訂號
- 網頁版發佈路徑帶主版號（例：`/barcode/v1/barcode-scan.js`），主版號變更時舊路徑保留
- 通訊協定 `v` 欄位與主版號一起變更
- 每次變更記在 `CHANGELOG.md`

## 13. 與 IPC2DO 現有程式的對應（尚未改為引用本模組）

| IPC2DO 現有位置 | 對應模組 | 後續改法 |
|---|---|---|
| `_android/.../ScannerActivity.java` | `BarcodeScannerActivity`、`BarcodeRules`、`ReadVoter`、`ZxingFallback` | App 改用 `ScanContract`；刪除 ScannerActivity |
| `_android/.../MainActivity.java` 的 `IPC2DOApp.scanQr／takeQr`、`deliverQr`（postMessage `'*'`） | `WebViewScanBridge` | 改用 `WebViewScanBridge.install()`，移除舊 JS 介面與廣播（同時處理資安議題 S-M6） |
| `_portal/scan.html` | `web/scan.html`＋`barcode-scan.js` | 發佈模組 web 目錄到 GitHub Pages，入口改用新掃描頁 |
| `Script.html` 的 `decodeQrFile`、`zxingDecodeImage`、`loadZXingWasm`、`qrScanBtn` 分流、`nativeQrScan` | `BarcodeScan.decodeFile`、`BarcodeScan.scanLive` | 以 `getClientBundle` 一併載入或以 `<script>` 引用；保留 `appendQrText` 帶入需求說明 |
| `Modules.gs` 的 `SCAN_CONFIRM` 設定 | `confirm` 選項 | 呼叫 `scanLive({ confirm: state.scanConfirm })` |

建議改法順序：① 網頁版（IPC2DO 改引用 `barcode-scan.js`）② Android（App 改引用 `barcode-scanner` 模組）③ 以第 11.3 節實機驗收。
